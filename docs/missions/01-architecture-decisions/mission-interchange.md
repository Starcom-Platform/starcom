## Locked Decision #7, amended by MX7

**As it stood** (`MissionPackageBuilder.ts`; reaffirmed 2026-09-26 as N6): a
Mission Package carries objectives and its briefing, never raw linked report
content, and never Starcom analyst identities: collaborator names or keys.
Its author was fixed as "Starcom".

**What the audit found.** The Nostr event carrying every package is signed
by its publisher's own key, which therefore crosses with it. The second,
ML-DSA signature uses a key kept in that person's browser. Starcom, the
project, holds no key that signs anything. The fixed "Starcom" put the
application in the author's seat, which the owner rejected: it is "the
Individual (pubkey/npub/user) [who] is posting USING Starcom/Navcom as their
client interface", and liability belongs with "the individual who made the
post themselves".

**As it stands now.** The signer is the author, named by the callsign they
choose to publish, or by their key when they have none. Nobody else's
identity crosses: not collaborators, not reviewers, not a display name
learned inside Starcom, and never a legal name. Everything else in #7 holds
unchanged: objectives and briefing only, linked records as counts, positions
masked (decision D1, [mission-position-boundary.md](mission-position-boundary.md)).

## The manifest vectors had drifted, found while building MX2

The manifest vectors in `docs/spec/mission-vectors/`, which NavCom tests
against, were generated on 2026-09-01 and never since. They still showed the
four-tier `classification`, no asks (rev 5 added `objectives`), and
`"Starcom"` as author, and one was named for a rule rev 5 reversed
(`manifest-objectives-never-cross`). Starcom's own vector test compared each
vector only with itself, so the builder's drift went unseen for five weeks.

Regenerated with the profile, through the real builder: the author is a
callsign, the misnamed vector is now `manifest-objective-position-masked`,
and three vectors cover the profile, two of them refused (a city, and a
campaign marked claimed). The test now builds each vector again from the
mission stored in it, so the builder cannot drift from them unseen.
